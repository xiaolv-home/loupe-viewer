# 合同审阅

目标：交付一份律师/法务风格的**审阅意见书**：哪条有什么风险、为什么、怎么改（给出替换文本），按严重程度排序。

## 0. 先定立场

- 我方是哪一方（甲/乙、买方/卖方、委托方/受托方）？用户没说就从文件名、抬头、上下文判断，判断不了时在意见书开头写明“本意见默认站在××方立场”。
- 合同类型与交易背景（金额、期限、是否格式条款、是否涉外）。

## 1. 通读与结构化

`read_file` 读全文（长合同分段读完，不能只读开头）。整理：当事人、合同类型、标的、金额与支付、期限、关键时间节点、各条款编号与标题。

## 2. 逐项审查清单

| 模块 | 重点看什么 |
| --- | --- |
| 主体 | 名称与签章一致、统一社会信用代码、授权代表、分支机构签约能力、资质许可（如建设、医疗、增值电信） |
| 标的 | 规格/数量/质量标准是否明确可验收；服务范围与交付物是否列清；附件是否齐全 |
| 价款与支付 | 含税与否及税率、发票类型与开具时间、付款节点与条件、预付款保护、逾期付款责任、价格调整机制 |
| 交付与验收 | 交付时间地点方式、风险转移时点、验收标准与期限、“视为验收”条款、异议期 |
| 质量与保修 | 质保期起算、免费维修范围、质量问题处理时限 |
| 违约责任 | 是否对等；违约金比例（过高可能被调整，过低不足以约束）；赔偿范围是否含间接损失/可得利益；责任上限 |
| 知识产权 | 成果归属、背景知识产权、许可范围、侵权担保与赔偿 |
| 保密与数据 | 保密范围与期限、个人信息/数据处理的合规义务（个人信息保护法、数据安全法） |
| 解除与终止 | 单方解除条件是否对等、通知期、解除后的结算与返还 |
| 不可抗力 | 定义范围、通知与证明义务 |
| 争议解决 | 管辖法院（对我方是否便利）或仲裁机构名称是否准确唯一；适用法律 |
| 其他 | 通知送达地址条款、合同生效条件、份数、附件效力、格式条款提示义务（民法典第 496 条） |

常用依据（引用时写条文号，不确定的不要编条文号）：《民法典》合同编（第 464 条起），第 496–498 条格式条款，第 577–585 条违约责任（第 585 条违约金调整），第 590 条不可抗力，第 563 条法定解除。若安装了「中国企业法务顾问（含法规库）」技能，可用 `search_text` 在其法规库里检索原文核对。

## 3. 风险分级

- **高**：可能导致重大损失或合同目的落空（无限责任、单方任意解除、付款无保障、权属不清、管辖约定无效）。
- **中**：对我方明显不利但可控（违约责任不对等、验收标准模糊、发票条款缺失）。
- **低**：表述不规范、笔误、建议完善项。

## 4. 交付物

用 `write_file` 生成《{合同名}_审阅意见书.docx》，结构：

```
# {合同名称}审阅意见书

**审阅立场**：{我方}　**合同类型**：{类型}　**审阅日期**：{日期}

## 一、总体意见
（2–4 句：能否签署、最关键的 3 个问题）

## 二、主要风险及修改建议
| 序号 | 条款 | 风险等级 | 问题说明 | 修改建议（可直接替换的文本） |
| --- | --- | --- | --- | --- |

## 三、逐条修改意见
### 第 X 条 {标题}
- **原文**：……
- **问题**：……（依据：《民法典》第 X 条）
- **建议修改为**：……

## 四、需要补充的条款
## 五、签署前需核实的事项
（对方资质、授权、附件、签章等）
```

如果用户需要，再生成《{合同名}_修订建议稿.docx》：全文按建议修改，修改处用 **加粗** 标出，删除内容用 ~~删除线~~ 标出。

## 禁忌

- 不编造法律条文、案例或条文号；拿不准就写“建议咨询执业律师确认”。
- 不只说“建议明确”，要给出具体可替换的条款文本。
- 不遗漏附件和定义条款对正文的影响。
- 意见书末尾注明：本意见基于提供的文本，不构成正式法律意见。
