# 简历诊断与重写

目标：一份**更可能拿到面试**的简历，以及告诉求职者为什么这样改。

## 1. 收集材料

- `read_file` 读简历（PDF / Word / 图片都可以，图片会自动识别文字）。
- 目标岗位：用户给了 JD 就以 JD 为准；没给就根据简历推断方向，并在报告里说明“按××岗位优化”。

## 2. 诊断（招聘方视角）

**6 秒初筛**：姓名联系方式是否醒目；最近一份工作/最高学历是否一眼可见；岗位方向是否清晰；篇幅（应届 1 页，3–10 年 1–2 页）。

**硬伤**（必须修）：时间线断档或重叠未解释、错别字和术语错误、联系方式缺失、照片/个人信息过多、不同经历描述前后矛盾。

**内容质量**：逐条看经历描述——
- 只有职责没有结果（“负责……”“参与……”）→ 改写。
- 缺少规模信息（团队人数、用户量、金额、数据量、项目周期）。
- 与目标岗位无关的内容占篇幅过多。
- 技能栏堆砌名词、没有熟练度或证据。

**匹配度**：列出 JD 的 5–8 个关键要求，逐项标注简历中有无证据（有 / 弱 / 无）。

## 3. 改写方法

每条经历按 **“动作 + 对象 + 方法 + 结果”** 改写：

- 原：负责门店销售数据分析。
- 改：搭建 120 家门店的日销售看板（SQL + Excel），把周报制作时间从 1 天缩短到 1 小时，支撑区域经理每周调整排班。

规则：
- 以强动词开头：主导、搭建、优化、推动、落地、降低、提升。
- 数字优先：金额、百分比、人数、时长、排名。没有准确数字时用范围或频率，并在报告里提醒本人核实。
- **不编造**：简历里没有的数据写成 `【请补充：提升了多少？】` 这样的占位符，在报告里列出需要本人补充的清单。
- JD 的关键词自然地融入经历描述，不要堆在技能栏。
- 最相关的经历放前面，每段 3–5 条，最重要的放第一条。

## 4. 交付

1. 《{姓名}_简历诊断.docx》（`write_file`）：总体评价（3 句）、硬伤清单、逐条改写对照表（原文 / 改后 / 理由）、JD 匹配度表、需要本人补充的信息。
2. 《{姓名}_简历_优化版.docx》：完整新简历，结构——

```
# 姓名
电话 | 邮箱 | 城市 | 求职意向：××

## 个人优势
（3 条，每条一句话带证据）

## 工作经历
### 公司 · 职位　　　　2022.03 – 至今
- 成果型描述……

## 教育背景
## 技能与证书
```

（原简历有项目经历时，在工作经历后加「## 项目经历」，只写原简历里有的项目。）

## 5. 写文件前自查（必做）

把优化版里的每一段经历、每一个项目、每一个时间段逐一对照原简历：原简历里找不到的，删掉；找得到但细节是你补的，换成 `【请补充】`。确认后再调用 write_file。

## 禁忌

- 不虚构公司、职位、学历、证书、数字。
- **不新增原简历里没有的项目或经历**，也不要放“示例项目/模板项目”。如果觉得缺项目经历，只在诊断报告里建议补充什么类型的项目。
- 原简历里没有的任何事实——数字、时间、规模、成果、获得的认可、用过的工具——一律写成 `【请补充：……】`，不能写成确定的句子。改写只能重新组织和表达原有事实。
- 不写主观评价（“学习能力强”“抗压能力强”）而无证据。
- 不改变事实的时间顺序与任职时间。
